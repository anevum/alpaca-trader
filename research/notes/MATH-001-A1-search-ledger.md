# MATH-001-A1

## Immutable hypothesis and search-exposure ledger

**Project:** MATH-001 — Discovery Reliability  
**Artifact:** MATH-001-A1  
**Status:** IMPLEMENTED  
**Claim class:** ANEVUM application  
**Production authority:** NONE

### Purpose

MATH-001 cannot control false discoveries if RHEN remembers only successful ideas. A1 makes search history a durable object.

Every research hypothesis must therefore be represented as:

1. a normalized research family;
2. an immutable scientific-hypothesis definition;
3. zero or more immutable candidate-variant definitions;
4. an append-only event history describing proposal, data exposure, inspection, rejection, freezing, stage opening, confirmation, replication, or archival.

The ledger is not a scorecard. It is the record required by later multiplicity mathematics.

### Identity

Family identity is deterministic from the normalized family name.

Hypothesis identity is deterministic from a canonical definition hash. Scientific hypotheses and candidate configurations are distinct ledger objects. Renaming a proposal or incrementing a proposal revision does not erase a definition that has already been examined.

Search-event identity is deterministic from its stable event key.

### Search generation

Agent-generated hypotheses record:

search_generation = proposal_revision - 1.

This is provenance, not a statistical penalty. Later MATH-001 multiplicity work may use generation, family structure, and cumulative exposure when comparing procedures.

### Exposure

The database maintains cumulative counts over the complete append-only history, including:

- hypothesis families examined;
- scientific hypotheses examined;
- candidate variants examined;
- proposal events;
- data-access events;
- result-inspection events;
- terminal rejections;
- contaminating events;
- latest search event.

A proposal generated by Research Agent is persisted even when deterministic design review rejects it. Failed proposals still consume search exposure.

### Data contamination

A search event may set data_contaminating=true when the hypothesis or variant has observed information that makes the same observations unsuitable as untouched confirmation.

This flag does not automatically decide whether a corpus is invalid. It creates durable evidence for later stage-gate and multiplicity logic.

### Historical backfill

A1 does not start the counter at zero.

The canonical migration backfills:

- controlled continuation;
- pullback reclaim;
- compression breakout;
- relative-strength impulse;
- opening-breakout retest;
- Residual Downshock Rebound v2.1.

The five Edge Discovery v1 families retain their terminal rejected state.

Residual Downshock Rebound v2.1 is recorded as terminal/archived after its development corpus-quality failure, not as a performance rejection.

### Append-only rule

The three canonical tables are append-only:

- private.trading_research_hypothesis_families
- private.trading_research_hypotheses
- private.trading_research_search_events

UPDATE and DELETE are rejected by database triggers. New information is represented by a new event or a new immutable definition.

### Runtime integration

Research Agent proposal generation now creates a deterministic search-ledger artifact alongside the proposal.

When persistence is enabled, the gateway records the audit run and search-ledger artifact together through an idempotent path. The canonical evidence packet exposes only compact search-exposure summaries and recent definitions/events, so the semantic reviewer can avoid recycling examined variants without receiving control authority.

### Security and authority

A1 does not:

- open DEVELOPMENT, VALIDATION, HOLDOUT, or quarantine;
- change methodology-freeze authority;
- alter live strategy, universe, risk, sizing, execution, broker behavior, or capital allocation;
- calculate the final multiple-testing correction;
- declare an edge confirmed;
- promote a challenger.
