# Bounded research code promotion

The canonical research runtime is `iren-runtime-boundary-20260930`.
GRAEN's existing worker inspects durable exhaustion states on each tick and
advances one engineering step using the existing authenticated GRAEN gateway.

The complete prespec, corpus exposure ledger, hash, epoch and research-only
authority are required. A freeze transaction writes the prespec artifact before
the next tick can create a branch. An absent exposure ledger is not evidence
that a corpus is untouched. Historical padding must be included in exposure.

Each new branch is based on the current canonical SHA. Canonical movement
abandons the attempt and starts a fresh branch, with at most three attempts.
No force push, branch protection bypass, model call, or new credential occurs.

The compiler supports bar-flow pressure. It emits exactly three files: a
generated research module, a frozen JSON specification, and candidate tests.
Only exact regenerated bytes are accepted; arbitrary Python, symlinks,
deletions, renames, controller/CI edits and live RHEN paths are not autonomous
operations. Extending the trusted compiler requires a separate reviewed change.

The primary GitHub GraphQL commit operation falls back to the existing Git Data
REST API only on transport/service failures. Authorization denials never trigger
a fallback. Ambiguous timeouts reconcile branch contents before another write.

PR merge requires the expected head, unchanged canonical base, exact allowed
diff and all jobs in the trusted CI workflow. Missing, skipped, cancelled, stale
or failed checks do not authorize merge. The GitHub merge endpoint enforces
repository protection; no admin bypass is used.

A matching fresh executor heartbeat and deployment ID must follow the merge.
Only then may the gateway atomically queue DEVELOPMENT and persist branch,
commits, PR, CI, deployment, hash and epoch provenance. A competing RUNNING
research job prevents this transition.

Generated hypotheses use an exclusive stage end with no future fetch padding.
Validation and holdout require a durable passing predecessor for the exact hash
and epoch. Completed stages are read from their artifact and never recomputed
because a continuation response was lost.

## Existing infrastructure authorization boundary

The session's connected GitHub App is a permitted bootstrap/write fallback.
It is not a credential available to a Railway process. The deployed IREN and
GRAEN service configurations inspected on 2026-10-01 expose no runtime GitHub
credential or connector bridge.

The controller therefore fails closed with
`runtime_github_authorization_not_configured` after a valid specification is
frozen. It supports an already-authorized `GRAEN_RESEARCH_GITHUB_TOKEN`; this
change does not create, copy, rotate or install any credential. Configuring a
new authorization boundary is not accomplished by pretending the session's
connector is callable by a deployed service.

No real FLOW-PRESSURE-002 prespec or complete exposure ledger was available in
the inspected canonical state. The test fixture uses synthetic year-2000
boundaries, is explicitly test-only, and must never seed a real campaign.

The automated tests demonstrate primary-write failure followed by fallback,
PR, CI, deployment verification and resume using simulated infrastructure.
They do not constitute a deployed market-research demonstration.

Ordinary transport interruptions retry idempotently. A failed trusted compiler
or methodology test remains blocked with the frozen specification intact; the
controller cannot safely rewrite its own policy, compiler or CI to turn a
failure into a pass.
